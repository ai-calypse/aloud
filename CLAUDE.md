# Aloud

Cross-platform (macOS + Windows) voice dictation. Hold a key, speak, and clean
text lands in whatever app has focus.

Rust does the work, React draws the pixels, Tauri v2 glues them together.
This is a port of a macOS-only Swift app, which stays the reference
implementation until parity — see `PROGRESS.md` for what has landed.

## Layout

```
apps/desktop/          Tauri app
  src-tauri/src/       thin orchestration only — logic belongs in a crate
  src/                 React + TypeScript
  src/lib/bindings.ts  GENERATED by tauri-specta. Never hand-edit.
crates/
  audio/               mic capture (cpal), resampling
  hotkey/              global hotkeys: CGEventTap / WH_KEYBOARD_LL
  llm/                 OpenAI-compatible chat, prompts, rate limits
  notes/               markdown notes + search, app data paths
  paste/               clipboard snapshot/restore, synthetic paste
  transcribe/          local whisper.cpp + cloud whisper
```

## Commands

```sh
pnpm install                # once
pnpm dev                    # run the app
pnpm build                  # bundle (.dmg / .app / .nsis)
cargo test --workspace      # all Rust tests
cargo clippy --workspace --all-targets   # must be warning-free
cargo fmt --all
pnpm --filter @aloud/desktop typecheck
```

Rust lives in `~/.cargo/bin` — `export PATH="$HOME/.cargo/bin:$PATH"` if
`cargo` is not found. Building `transcribe` needs `cmake` (whisper.cpp).

## How this codebase is organised

**Logic goes in a crate, not in `src-tauri`.** Crates have no Tauri
dependency, so they are testable with `cargo test` and runnable from an
`examples/` binary without launching the app. `src-tauri` should only wire
crates to commands and events. The Swift app's 4,000-line `AppState` god
object is exactly what this structure exists to avoid.

**The frontend never guesses at Rust's types.** `tauri-specta` regenerates
`src/lib/bindings.ts` on every debug run. Add a `#[tauri::command]`, run the
app, and the typed binding appears.

**Platform differences live in the crate that owns them**, behind `#[cfg]`,
never leaking into app code. `hotkey` is the model: one pure reducer, two
thin OS backends.

## Conventions

- **Comments say why, not what.** A comment earns its place by explaining a
  constraint the code cannot: why `FastFixedIn` and not the FFT resampler,
  why a daily rate-limit outranks `retry-after`. Never narrate the next line.
- **Mark deliberate corner-cuts** with a `ponytail:` comment naming the
  ceiling and the upgrade path, e.g. `// ponytail: linear scan — SQLite FTS
  is the upgrade path if it gets slow`.
- **Test the logic that can silently be wrong**, not the getters. Every bug
  found so far (empty WAVs, one-shot hotkeys re-firing) got a regression test
  named for the failure.
- **Port intent, not syntax.** Where Swift logic was tuned on real data —
  the hallucination thresholds, the rate-limit header precedence — port it
  verbatim and say so. Where it was working around AppKit, use the better
  Rust tool.
- Keep it minimal. If two lines do it, do not write ten.

## Non-obvious things that will bite you

- **whisper.cpp prints to stdout from C.** Without
  `whisper_rs::install_logging_hooks()`, model load takes 19s instead of
  200ms and the log fills with junk.
- **`ProjectDirs::data_dir()` is wrong for this app.** It yields
  `app.Aloud.Aloud` on macOS; the Swift app uses a plain `Aloud` folder and
  migration reads from it. Use `aloud_notes::data_dir()`.
- **Tauri's `global-shortcut` plugin is unusable here.** No modifier-only
  bindings, no hold-vs-tap, cannot swallow events. Hence `crates/hotkey`.
- **AppleScript-synthesized keys arrive with keycode 0.** `osascript` cannot
  test the hotkey path; post a real `CGEvent` instead.
- **`specta`/`tauri-specta` are exact-pinned RCs** that move in lockstep. Do
  not loosen to `^`.
- **Bindings are emitted relative to the crate dir**, so `cargo run -p aloud`
  must run from `apps/desktop/src-tauri`. `pnpm dev` handles this.

## Verifying

Unit tests do not prove OS integration, and this app is almost entirely OS
integration. Anything touching audio, keys, or the clipboard gets an
`examples/` binary that exercises real hardware, and the result goes in the
PR body. Two of the bugs above passed their unit tests before real hardware
disproved them.

## Git

One branch per feature, PR into `main`. PR bodies state what was verified
and, honestly, what was not — every PR so far carries a ⚠️ noting the Windows
path is unexercised.
